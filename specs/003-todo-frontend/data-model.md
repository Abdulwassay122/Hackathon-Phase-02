# Data Model: Todo Frontend Integration

**Feature**: 003-todo-frontend
**Date**: 2026-02-07
**Phase**: 1 - Design & Contracts

## Purpose

This document defines the TypeScript type definitions and data structures used in the frontend application. The frontend does not own the data model - it mirrors the backend API contracts. All types are derived from the backend API responses defined in Phase 2.

## Core Types

### Task

Represents a todo item as returned by the backend API.

```typescript
/**
 * Task entity from backend API
 * Matches the Task model from backend (Phase 2)
 */
export interface Task {
  /** Unique task identifier (auto-generated by backend) */
  id: number;

  /** Task title (required, max 200 characters) */
  title: string;

  /** Task description (optional, max 1000 characters) */
  description: string | null;

  /** Completion status */
  completed: boolean;

  /** Owner user ID (set by backend from JWT token) */
  user_id: number;

  /** Creation timestamp (ISO 8601 format) */
  created_at: string;

  /** Last update timestamp (ISO 8601 format) */
  updated_at: string;
}
```

### TaskCreate

```typescript
/**
```

### TaskUpdate

Request payload for updating an existing task.

```typescript

 * Payload for PUT /api/tasks/{id}

export interface TaskUpdate {

  title?: string;

  /** Updated task description (optional, max 1000 characters) */
  description?: string | null;

  /** Updated completion status (optional) */
  completed?: boolean;
```


## Type Guards

Utility functions for runtime type checking.

```typescript
/**
 * Type guard to check if a value is an ApiError
 */
export function isApiError(error: unknown): error is ApiError {
  return (
    typeof error === 'object' &&
    error !== null &&
    'detail' in error &&
    typeof (error as ApiError).detail === 'string'
  );
}

/**
 * Type guard to check if a task is valid
 */
export function isValidTask(task: unknown): task is Task {
  return (
    typeof task === 'object' &&
    task !== null &&
    'id' in task &&
    'title' in task &&
    'completed' in task &&
    'user_id' in task &&
    typeof (task as Task).id === 'number' &&
    typeof (task as Task).title === 'string' &&
    typeof (task as Task).completed === 'boolean' &&
    typeof (task as Task).user_id === 'number'
  );
}
```

## Notes

**Data Ownership**: The frontend does not own the data model. All types mirror the backend API contracts from Phase 2. Any changes to the data model must originate from the backend.

**Type Safety**: TypeScript provides compile-time type checking. However, runtime validation is still necessary when receiving data from the API (use type guards).

**Validation**: Client-side validation is for UX only. The backend enforces all security and business rules. Never trust client-side validation alone.

**Null vs Undefined**: Use `null` for optional fields that can be explicitly set to "no value" (matches backend). Use `undefined` for optional function parameters or omitted fields.

**Date Handling**: All timestamps are ISO 8601 strings from the backend. Convert to Date objects in components if needed for display or manipulation.
